# تحديث 21 نوفمبر 2026 — الحسابات وCRM ومتابعة المشاريع

## نطاق الدفعة

استديو نطاق مستبعد بناء على طلب المستخدم؛ ملفاته المنشورة لم تتغير، وأعمال تنظيمه غير المنشورة محفوظة محليًا خارج المستودع. النسخ الاحتياطي اليومي مؤجل بطلب المستخدم، ولم تُغير إعداداته أو تُنشأ أسرار جديدة.

## متابعة المشاريع: نقل مختصر بلا حذف بيانات

أضيف `nitaq_engineering_workspace_read_v3` في تحديث 021. يعيد استخدام فحص العضوية والصفحات والمراجعة في `read_v2`، ثم يرسل لقطات المراحل والسجل المتكررة مرة واحدة مع مراجع. الواجهة تعيد بناء مستندات مستقلة كاملة قبل العرض أو المقارنة أو الحفظ. لم تُعدل بيانات المشاريع المخزنة أو دوال الكتابة أو شرط التعارض. عند عدم وجود الدالة فقط، تستخدم الواجهة `v2` ثم `v1`؛ رفض الصلاحيات أو تعذر الشبكة لا يؤدي إلى تجاوز الحارس.

إذا كان تمثيل القاموس أكبر من الصفحة الأصلية، تُرسل الصفحة الأصلية. لا توجد خسارة سجل، ولا تأجيل قراءة تفاصيل لازمة للحفظ، ولا ضغط بطريق تقصير القيم. تبقى كلفة الذاكرة النهائية للمستندات الكاملة؛ هذا تحسين نقل وليس ترقيمًا من الخادم لكل شاشات التطبيق.

تحقق القراءة على الإنتاج أعاد تطابق المستندات الكاملة للمشاريع الـ12: 292,495 بايت قبل النقل مقابل 248,268 بايت بعده، بتوفير نحو 15.1%. لم يُنفذ حفظ تجريبي على مشاريع العملاء.

## الحسابات وCRM: تنظيم المصدر

نُقل مصدر الحسابات إلى 8 ملفات في `src/accounting/`، وCRM إلى 4 ملفات في `src/crm/`. يحدد `manifest.json` الترتيب، ويجمعه البناء في نطاق JavaScript واحد كما كان سابقًا. `scripts/frontend-source.mjs` يقرأ الملفات ويتحقق من أسمائها وعدم تكرارها، وتستخدمه أدوات البناء والفحص.

ثبت تطابق جسم JavaScript المولّد للحسابات وCRM حرفيًا مع النسخة السابقة، باستثناء تعليق مسار المصدر. لم تُغير هذه الخطوة قواعد الإيرادات والرواتب والضرائب أو طريقة حفظ CRM. الحذف الظاهر لملفي JSX القديمين هو نقل مصدر إلى الملفات الجديدة، وليس حذف وظائف.

## سياسات القاعدة

- الحسابات: تثبيت `search_path` لدالة Trigger المسماة `nitaq_touch`، وتقييم `auth.uid()` مرة لكل عبارة في سياسة قراءة الملف الشخصي.
- CRM: التحسين نفسه لنداء `auth.uid()` في أربع سياسات قائمة. لم تتغير أدوار السياسات أو شروط السماح والمنع أو حماية الكتابة المباشرة.
- اختفت تنبيهات `auth_rls_initplan` للمشروعين بعد التطبيق، وتنبيه `function_search_path_mutable` في الحسابات. دالة القراءة الجديدة تزيد تنبيه الدوال المحروسة المتاحة للمسجلين بواحد؛ صلاحية anon مرفوضة، والدالة تفحص عضوية مساحة العمل.
- لم تُحذف فهارس أو سياسات سماح بناء على إحصاءات الاستخدام وحدها، ولم يتغير إعداد حماية كلمات المرور المسرّبة.

## اختبار الواجهة

استُخدم Edge معزول ببيانات وحسابات وهمية وخدمة API بديلة. ليس اختبارًا لحسابات الفريق أو دليلًا على كل حالات التشغيل الحي.

- الحسابات: فتح صفحات المشاريع والتنقل في القوائم.
- CRM: سجل العملاء والعملاء والتقارير والمستخدمون.
- متابعة المشاريع: قراءة المساحة، ونماذج المشروع والمرحلة والمستندات، وإغلاقها دون تغيير اللقطة.
- اختبار عرض 1440×900 و390×844 للأنظمة الثلاثة، بلا أخطاء JavaScript وبلا خروج جسم الصفحة أفقيًا.
- إصلاح تباين زر «أوقات العمل» في رأس متابعة المشاريع؛ كان يرث لونًا أبيض على خلفية بيضاء.
- معاينة الطباعة الفعلية تفتح الصفوف المعروضة، وتتضمن رقم المشروع، وتستبعد حقول التحرير وعناصر التحكم عند تفعيل نمط الطباعة، دون تغيير البيانات أو إرسال أمر طباعة ورق.

لقطات الاختبار ونتائجه محفوظة محليًا في `outputs/three-systems-browser-20261121/`، خارج ملفات النشر. آلية الاختبار المحلية في `work/verify-three-systems-20261121.py`، وتستخدم بيانات اصطناعية فقط.

## التحقق

- `npm run check`: فحوص المصدر والبناء والربط والطباعة والموبايل والسجل والتعارضات والقاموس.
- `check:database`: قراءة مختصرة مطابقة بالكامل، وحفظ تعديل بعد فكها، واستقلال لقطات السجل في الذاكرة، وصفحات فارغة وقيم null قديمة ورفض غير الأعضاء، مع اختبارات الحسابات وCRM بعد تحسين السياسات.
- `simulate:office-day`: الحفظ المتزامن والتعارض وفقد الرد والاسترجاع إلى قاعدة وهمية أخرى نجحت على 5000 مشروع، مع بقاء 60000 صف مرحلة.
- `check:live`: تحقق من وجود واجهات الأنظمة الثلاثة المطلوبة بعد تطبيق تحديثات القاعدة.

هذه الدفعة لا تحول الاستديو إلى حفظ مشترك، ولا تفعل النسخ اليومي المؤجل. تحسين النقل لا يلغي الحاجة لاختبارات قبول الفريق ومتابعة قياسات الإنتاج.
