# READY حالة أساسية لكل المراحل عدا التصميم

- إضافة READY إلى القائمة الأساسية المشتركة لكل مراحل الجهات والمناقصة، وإلى القائمة الثابتة لتنسيق المخططات.
- التصميم يحتفظ بحالاته القديمة ولا يقبل READY.
- المعنى الافتراضي جاهز للتقديم، وفي التنسيق جاهز للمطابقة والمراجعة. تظهر في مفتاح الألوان والتقارير والفلاتر وتفاصيل المرحلة والجدول والموبايل.
- عدم تكرار READY إذا كانت موجودة في القوائم المخصصة سابقًا؛ لا تُحذف أي حالة مشروع أو معنى/لون مخصص من الإعدادات.
- READY تصبح أساسية ولا يمكن حذفها عبر مسار حذف الحالة المخصصة السابق.
- تعديل normalizeCoordination حتى لا يعيد READY إلى REQ عند تحميل أو استعادة البيانات.
- migration 20261118110729_ready_for_coordination.sql توسع شرط قبول حالة التنسيق فقط. لم تتغير أي قيم مشروع أو صلاحيات أو شروط إجازة البناء. READY لا تعني اعتمادًا ولا تستوفي شروط التصريح.
- تم التأكد من الإنتاج أن شرط التنسيق يتضمن READY وأن التحديث مسجل. لا حاجة لإعادة تطبيقه.
- نجح npm run check واختبار PostgreSQL المعزول الذي يحفظ ويعيد قراءة READY في كل المراحل غير التصميم، ويرفضها للتصميم، ويؤكد بقاء شروط الإجازة وسلامة إعادة تطبيق migration.
- تعذر استكمال التحقق البصري عبر المتصفح في هذه الجلسة؛ فحص القاعدة النهائي تم بالموصل قراءة فقط. النشر يُتحقق منه عبر GitHub Actions والملفات المنشورة.
